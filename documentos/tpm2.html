🔐 TPM 2.0 – Derivação de Chaves Baseadas em Hardware

Este documento descreve como utilizar o módulo TPMStart para derivar chaves criptográficas a partir do segredo persistente armazenado na NVRAM do TPM 2.0. A abordagem garante que cada chave seja única por finalidade (via salt) e que o segredo raiz (pepper) nunca seja exposto fora do módulo.

📌 Pré‑requisito: O servidor principal já deve ter sido inicializado com a flag --accepttp2mchanges=yes para consentir a criação do índice NVRAM, se necessário. O módulo TPM deve ter sido inicializado com sucesso via TPMStart::initTPM().

1. Arquitetura Geral

O sistema é composto por duas camadas:

  • Camada de baixo (tpm2) – gerencia a comunicação com o TPM, lê/cria o pepper na NVRAM e oferece um getter seguro (getPepper).
  • Camada de alto nível (TPMStart) – fornece uma função de derivação (deriveKeyFromPepper) que utiliza o pepper + salt obrigatório para gerar chaves de qualquer tamanho (até 1024 bytes).

O fluxo de dados é unidirecional e seguro:

TPM (NVRAM) → pepper (64 B) → deriveKeyFromPepper(salt) → chave derivada
                                      ↑
                                 (salt fornecido pelo chamador)

O pepper nunca é retornado diretamente para o chamador; apenas a chave derivada, que depende do salt e do pepper, é exposta.

2. Funções Públicas (API)

2.1 bool initTPM(memorymanager::MemoryManagerThread* mm)

Inicializa o gerenciador TPM, lê ou cria o pepper persistente. Deve ser chamada uma única vez durante a inicialização do sistema. Retorna true em sucesso.

2.2 void shutdownTPM()

Finaliza a sessão TPM e libera recursos. Chamada durante o encerramento controlado.

2.3 bool deriveKeyFromPepper(...)

Função principal para obtenção de chaves derivadas. 

bool deriveKeyFromPepper(
    memorymanager::MemoryManagerThread* mm,  // reservado (futuro uso com arena)
    const uint8_t* salt,                     // OBRIGATÓRIO – diferenciador de propósito
    size_t salt_len,
    uint8_t* out_key,                        // buffer de saída
    size_t out_len,                          // tamanho desejado (≤ 1024)
    char* out_error,                         // opcional – mensagem de erro
    size_t err_size
);
  • salt – obrigatório (não pode ser nulo nem vazio). Define o domínio da chave (ex: "encrypt_db", "auth_jwt").
  • out_len – tamanho da chave desejada em bytes (máximo 1024).
  • Retorno – true se a derivação for bem‑sucedida, false com erro descrito em out_error.

3. Como Usar em Outros Scripts/Módulos

Para utilizar a derivação de chaves em qualquer parte do sistema (ex: módulo de criptografia, autenticação, armazenamento seguro), siga os passos abaixo.

3.1 Inclua o cabeçalho

#include "start_tpm.hpp"   // ajuste o caminho conforme sua estrutura

3.2 Certifique‑se de que o TPM foi inicializado

No main() do servidor, TPMStart::initTPM() já é chamado. Se estiver escrevendo um módulo separado que roda após a inicialização, pode confiar que g_tpm_initialized estará true.

3.3 Derive a chave para seu propósito

Escolha um salt único e descritivo para cada finalidade. Não reutilize o mesmo salt para finalidades diferentes (isso quebraria o isolamento).

Exemplo – chave de 32 bytes para criptografia de arquivos:

uint8_t file_key[32] = {0};
char err[256] = {0};
const char* salt = "file_encryption_v1";

if (TPMStart::deriveKeyFromPepper(
        &g_memory_manager,                      // seu MemoryManagerThread
        reinterpret_cast<const uint8_t*>(salt), strlen(salt),
        file_key, sizeof(file_key),
        err, sizeof(err))) {
    // Use file_key para AES‑256‑GCM, por exemplo
} else {
    std::cerr << "Falha ao derivar chave: " << err << std::endl;
}

Exemplo – chave de 64 bytes para autenticação HMAC:

uint8_t hmac_key[64] = {0};
const char* auth_salt = "hmac_session_v2";
if (TPMStart::deriveKeyFromPepper(
        &g_memory_manager,
        (uint8_t*)auth_salt, strlen(auth_salt),
        hmac_key, sizeof(hmac_key),
        nullptr, 0)) {
    // Usar hmac_key em HMAC‑SHA512
}

3.4 Limpeza

A função deriveKeyFromPepper já limpa internamente todos os segredos. O chamador deve zerar o buffer da chave após o uso (ex: com OPENSSL_cleanse ou memset seguro) para evitar vazamentos em memória. 

// Após usar a chave:
OPENSSL_cleanse(file_key, sizeof(file_key));

4. Boas Práticas e Recomendações

  • Salt único por propósito – use strings descritivas e, se possível, inclua uma versão (ex: "auth_jwt_v2"). Isso permite rotacionar chaves sem afetar outros usos.
  • Nunca armazene o pepper – ele reside apenas na NVRAM do TPM e é lido sob demanda.
  • Chaves curtas? – o HKDF suporta qualquer tamanho; para AES‑256 use 32 bytes; para HMAC‑SHA512 use 64 bytes.
  • Erros – sempre verifique o retorno e, se desejar, forneça um buffer de erro para diagnóstico.
  • Thread safety – a função deriveKeyFromPepper não é thread‑safe; proteja com mutex se for chamada concorrentemente.
⚠️ Atenção: A função deriva chaves usando HKDF‑SHA256. O tamanho máximo atual é 1024 bytes (limitado pelo buffer na stack). Se precisar de mais, ajuste a constante MAX_TEMP em start_tpm.cpp e recompile.

5. Exemplo Completo de Integração

Suponha que você esteja implementando um módulo de criptografia de arquivos (crypto_file.cpp). O código pode ser estruturado assim: 

#include "start_tpm.hpp"
#include "memory_manager_thread.hpp"

bool encryptFile(const std::string& filename,
                 memorymanager::MemoryManagerThread* mm) {
    // 1. Derivar chave de 32 bytes para criptografia
    uint8_t key[32] = {0};
    char err[256] = {0};
    const char* salt = "file_encryption_master";

    if (!TPMStart::deriveKeyFromPepper(mm,
                                       (const uint8_t*)salt, strlen(salt),
                                       key, sizeof(key),
                                       err, sizeof(err))) {
        std::cerr << "Erro ao derivar chave: " << err << std::endl;
        return false;
    }

    // 2. Usar a chave para criptografar (ex: AES‑GCM)
    // ...

    // 3. Limpar chave
    OPENSSL_cleanse(key, sizeof(key));
    return true;
}

6. Segurança e Considerações Finais

  • Hardware Root of Trust – a segurança depende da integridade do TPM. Se o TPM for resetado, o pepper é perdido e o sistema deve ser reconfigurado.
  • Backup – considere exportar o pepper (criptografado) para um local seguro em caso de falha do TPM, embora isso reduza a segurança.
  • Auditoria – registre quando chaves são derivadas (mas nunca registre as chaves ou o pepper).
  • Atualização – se o salt mudar, a chave derivada muda completamente; planeje uma estratégia de migração.
✅ Conclusão: O módulo TPMStart oferece uma API simples e segura para transformar o segredo do hardware em chaves criptográficas práticas, sem expor o segredo raiz. Ao adotar esta abordagem, seu sistema ganha uma camada extra de proteção contra ataques offline e engenharia reversa.
